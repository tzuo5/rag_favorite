# 频繁 EmbeddingError 的原因与修复

2026-10-04，America/Chicago。

根因是视频知识分块器与 LM Studio 客户端的长度计算不一致。
`embed_complete_text` 原来每 3000 个 Python 字符切分一次；客户端却用
`UTF-8 字节数 + 16 <= 已加载 context_length` 做保守的发送前检查。
当前模型加载上下文为 4096，因此客户端允许的文本字节数为 4080。
这个字节限制是项目自己的安全校验，不是 LM Studio 将上下文定义成字节。
中文和表情会使字符数与字节数明显不同，导致不到 3000 字的文本也被拒绝。

## 本机证据

模型 `text-embedding-qwen3-embedding-0.6b` 已加载，文件摘要与固定配置一致。
短文本实测能返回 1024 维向量。1300 个“中”为 3900 字节，编码成功；
1500 个“中”为 4500 字节，触发客户端的 context limit 错误，尚未发送编码请求。

利用失败任务保留的转写和视觉帧批次缓存重建文本样本，不额外调用 CCR：

| 7b0f3478 | 1788 | 4602 | 发送前 context limit 错误 | 1024 维，范数 1 |
| ac4be46e | 2080 | 5206 | 发送前 context limit 错误 | 1024 维，范数 1 |
| c795ae5f | 1714 | 4298 | 发送前 context limit 错误 | 1024 维，范数 1 |

样本用于验证这个可复现的长度问题；历史日志只有通用 `EmbeddingError`，
不能据此断言每条旧错误都属于同一原因。

## 修改与验证

- LM Studio 客户端公开经过模型身份校验的文档字节预算。
- 视频分块同时遵守原有 3000 字符上限和模型实际加载配置对应的字节预算。
- 切分保持 Unicode 字符完整，重组后与原文完全一致，不截断知识。
- 原来能成功的短输入保留原有分块；模型、文件摘要、1024 维空间保持一致。
- 超限错误增加明确代码 `EMBEDDING_CONTEXT_LIMIT`，便于定位后续同类失败。
- 110 项相关测试通过，覆盖中文、英文、表情、多种上下文大小、完整内容保留、
  实际客户端请求校验，以及本地 / 云端 Embedding 和视频回归测试。
- 三份失败任务缓存通过当前真实 LM Studio 服务验证成功。
- Ruff 与 `git diff --check` 通过。
