公开版本已匿名化本机入口和任务标识；原始验收记录保留在本地。
## 2026-10-12：限速与恢复门禁修订

以下规则取代本页旧版本中的“不限速”和“300012 自动换节点”。旧验收记录保留为历史证据。

- 生产路线默认 `pool`。显式 `direct_diagnostic` 在同一回环代理内使用 Xray 普通
  `freedom` 出口；浏览器、API 和页面媒体保持同一路线，无隐式直连回退。
  诊断不旋转节点、不增减成功下载账本、不解锁队列；重启回到 `pool`。
- 页面/API 操作共享至少 60 秒间隔、滚动一小时最多 30 次的持久预算。账号、收藏、
  关注、作者、笔记、程序触发的登录导航均计费，失败也占用预算。
  页面附带资源和媒体 HTTP 请求分别记录；30 次不是全部 HTTP 请求上限。
- 初始验收和观察每小时最多尝试 6 条笔记。使用缓存元数据发起媒体下载、失败重试
  也计入笔记预算；完整缓存命中不新增 VPN 下载成功数。预算跨重启、换节点保留。
- 保留完整媒体通过校验后计数、每 80 条轮换、媒体串行、单一下载消费者、
  会话锁覆盖完整下载和取消后的线程收尾。新节点先验证账号和一条笔记。
- 普通网络故障在原节点分别等待 60、300 秒，之后最多使用一个备用节点；
  备用失败暂停。300012、验证码、身份异常、429、-101 等未知会话状态暂停所有自动
  小红书入口，既不当作线路错误也不因冷却到期或单次成功自动解除。
- 恢复分为 `paused → validated → acceptance → observation → steady`。
  读取验证只到 `validated`。验收只准入三条有完整来源的不同笔记；收藏和关注此时
  仍暂停，其他来源及已下载内容的离线阶段继续。任何样本终止失败保留暂停。
- 入库验收要求媒体校验收据、任务 `complete`、发布阶段 `done`、真实语义检索命中、
  携带检索版本分页读取到 `complete=true`。三条通过后才进入低速观察；至少两小时
  且额外六条不同笔记完整通过同样验收，才提升到每小时 12 条，滚动 24 小时最多
  100 次笔记尝试。新风险会重置恢复阶段并关闭准入。
- 面板兼容原有字段，新增路线、检查时间、预算、恢复阶段、暂停原因及分路线诊断
  结果。截图显示捕获时间，并明确“截图刷新不等于重新验证”。

这些频率是本项目保守初始值，不是平台公布的安全阈值。
直连出口依据 [Xray Freedom 官方文档](https://xtls.github.io/en/config/outbounds/freedom.html)。

本机管理命令（使用现有会话，不另建浏览器资料）：

```bash
.venv/bin/python scripts/xhs_access_recovery.py status
.venv/bin/python scripts/xhs_access_recovery.py diagnose --route direct_diagnostic --wait
.venv/bin/python scripts/xhs_access_recovery.py diagnose --route pool --wait
.venv/bin/python scripts/xhs_access_recovery.py acceptance_start
.venv/bin/python scripts/xhs_access_recovery.py acceptance_check
```

`diagnose` 每条路线只运行一轮；等待仅查询本地状态。遇到新的风险即结束该轮，
不扫节点。面板“检查读取能力”的再次显式检查至少间隔 30 分钟；用户完成新登录
交互后可以开始新的验证轮次。三条验收和观察的发布检查只访问本地 RAG。

## 下载与节点

- `xhs_session_service.py` 独占持久浏览器和 Xray 子进程；浏览器、签名 API、
  视频、图片和 Live Photo 共用显式代理。缺少代理或代理无法启动时等待，禁止回退直连。
- 一条视频通过完整传输、容器校验后计一次；一条图文的全部图片和可获取的 Live Photo
  下载验证完成后计一次。文字内容没有媒体下载时不计数。缓存命中、失败、重试和同一笔记
  的重复完成回报不重复计数。
- 会话锁覆盖完整媒体组，正常轮换发生在第 80 条完成后的下一次联网操作之前。
  图片和 Live Photo 提前在 download 阶段下载；OCR 在 prepare，模型分析在 LLM 阶段执行。
- 节点使用稳定配置指纹识别。当前节点、批次计数、完成账本、失败节点、切换代次和冷却
  写入私有文件。服务重启保留这些状态；完成收据与计数写入之间崩溃时，启动会核对补记。
- 明确线路错误或平台码 `300012` 提前切换；本轮失败的节点跳过。全池失败后复查首节点
  一次，仍失败则冷却 30 分钟。普通来源失效、本地工具错误、损坏文件不直接降低节点健康。
- 429 遵守 `Retry-After`，验证码、登录失效、账号不符和原因未知的访问拒绝暂停所有小红书
  自动入口。收藏成功不会清除笔记访问限制。账号恢复要求重新检查账号绑定及实际笔记读取。
- 启用统一代理后移除原先 15 秒间隔、每小时 60 篇配额和收藏页固定等待。
  保留原有流水线并发、磁盘预算、任务租约与暂停机制。
- `download-bundle.json` 与逐图收据保存校验和及已下载文件；短期来源元数据可复用。
  旧 ingestion 的独立浏览器、HTTP、小红书 yt-dlp 入口明确要求使用统一服务。
  非小红书入口和离线处理保持原有功能。

运行配置为视频配置中的 `xhs_proxy_config` 路径。其私有 JSON 包含 `binary`、
`nodes_file`、`port`、`batch_size`，节点文件形如 `{"nodes": [...]}`。
本机使用现有 99 条节点、回环端口 18998、`batch_size=80`。
`acceptance_limit` 是部署期间的累计下载上限，依次设置 5、20；验收后移除此字段。
节点配置、浏览器资料和凭据均保留在忽略提交的 `.runtime` 中。

节点序号只表示连接线路，不保证出口 IP 固定或彼此不同。

## 桌面和网页

删除原生 `desktop_gui.py`、Qt 窗口测试和 PySide6 安装依赖。
网页共享配置移至 `runtime_profiles.py`；`rag-favorite-gui` 兼容命令改为启动默认浏览器。
桌面和应用菜单快捷方式由原安装器原地替换，其 Exec 为 `xdg-open` 和已配置的 HTTPS 地址。

使用方法：

1. 双击桌面 **RAG 任务控制台**，登录已有私有网页。
2. 在“账号”查看当前节点、本节点 `已下载/80`、累计计数、切换原因和冷却时间。
3. 用“暂停小红书访问／恢复小红书访问”控制小红书网络入口；平台验证仍通过原“登录与验证”处理。
4. 总队列的暂停和恢复仍在总览操作；关闭浏览器不停止后台处理。

网页服务和会话服务继续由原有 systemd 用户服务负责启动及故障重启。
本次没有进行整机重启测试。
