# 小红书少扫码改造与部署记录

公开版本已匿名化本机入口和任务标识；原始验收记录保留在本地。
2026-10-11。实施范围依据本轮批准的修改计划。技术部署和短期读取验收已完成；72 小时与七天的登录稳定性观察尚未完成，不能据此承诺固定登录期限。

## 已上线的行为

- 新增 `rag-favorite-xhs-session.service`，使用原来的 Google Chrome 持久 profile。登录、收藏、关注、作者分页和笔记读取统一经过权限为 0600 的本地 Unix socket，服务同时持有原 profile 文件锁。
- 使用浏览器当前 CookieJar 和真实 UA 生成签名并发送请求；Cookie 文件只作为原子发布的兼容导出，不反向覆盖 profile。每篇笔记不再重复启动浏览器或先发一次独立 HTTP 请求。
- 单账号逻辑请求至少间隔 15 秒，每小时最多读取 60 篇笔记；失败尝试计入额度，记录跨重启保留。浏览器内部子请求不等同于这些逻辑请求，60 不是平台保证的安全阈值。
- 预算等待、服务暂不可用和会话暂停不增加下载失败次数；任务释放执行槽后等待。关注续扫先检查本地积压，并复用未完成扫描的作者快照。
- 区分登录失效、验证、限流、访问限制、网络故障、单篇不可用及未知情况。账号、收藏和笔记路径各有状态；收藏成功不会解除下载暂停，旧事件也不能覆盖新的限制。
- 新增迁移 `0011_xhs_session_service.sql`。旧登录暂停被转成待核实记录。恢复只处理会话原因产生的阻塞，保留手动暂停、单篇坏来源和其他任务状态。
- 私有控制台增加小红书面板，提供二维码图片及解码链接、短信输入、限定在登录/验证码区域内的点击和拖动。操作绑定活动尝试及画面版本，十分钟超时；不提供任意导航或脚本接口。
- 空闲时不向小红书发保活请求。会话事件即时记录，本地每小时记录成功次数、状态和服务内存/CPU，供后续观察。

## 已验证与未验证的边界

真实账号验收复用了原有登录，没有要求用户重新扫码。账号校验、收藏一页（10 条）、关注列表（40 位作者）、笔记读取均成功；重启服务后再次确认原账号及正常待处理笔记仍可读取。

恢复采集后的快照记录了 3 个新完成的 download 阶段，同时有 download、prepare、llm 阶段运行。它们不是“新增 3 条已发布知识”的证明。快照中登录暂停为 false、下载暂停为 false，三个同步 timer 已恢复，原本停用的 summary worker 仍停用。

重启验收曾选到一条历史上已因 `XHS_SOURCE_TOKEN_REFRESH_UNAVAILABLE` 受阻的笔记，产生一次 unknown 事件。已修正候选查询，只选择正常待处理任务或会话原因阻塞的任务，并增加数据库回归测试。该历史事件没有从记录中删除；修正后的读取验证通过。

验证结果：

- 完整本地回归：440 passed、79 skipped；跳过项包含需显式启用的外部集成测试。
- 最终浏览器、手机接口、数据库及阶段队列定向验收：53 passed。
- 最终会话状态单元测试：17 passed。
- Ruff 和 `git diff --check` 通过。
- 真实 Chrome 使用合成页面验证二维码解码、短信提交、点击/拖动区域限制、过期请求拒绝、profile 重启保留和 390 像素手机页面布局。
- 私有 HTTPS 首页和新前端资源返回 200，未登录访问新会话接口返回 401；敏感响应禁止缓存。

本轮真实账号没有触发短信或验证码，所以没有宣称通过了真实平台的手机验证流程。平台页面以后改变时可能需要调整定位规则；目前已有会话不会为此主动清除。长期稳定性需要在有实际采集量的情况下观察，不能把“停止采集后未掉线”视为效果。

## 运行与恢复

手机入口：已有的 [私有 RAG 控制台](https://your-node.your-tailnet.ts.net)，使用原控制台登录方式，进入“小红书会话”面板。状态正常时无需点击登录。真正需要验证时在该面板操作；原账号匹配和笔记路径检查通过后，程序受控恢复。

私有文件位于 `.runtime/videorag/xhs-session/`：

- `session-state.json`：请求预算、各路径状态、累计计数。
- `session-events.jsonl`：脱敏故障事件。
- `observations.jsonl`：每小时本地观测，没有额外平台请求。
- `profile/`、`cookies.txt`：私有浏览器状态和兼容导出，禁止提交 Git。

部署备份和运行验收位于 `.runtime/xhs-session-rollout-20261011/`，包括原代码、原 profile、服务/队列状态及重启验收。部署没有修改公网入口、Tailscale 权限或模型驻留配置。

维护命令使用本仓库 `.venv/bin/python scripts/rollout_xhs_session.py status`。回滚入口为同一脚本的 `rollback`：先暂停新工作并等待执行中任务排空，停止新会话服务，保存当前 profile，再恢复部署前代码和当时的运行控制。数据库新增列保留，不回滚任务进度；若检测到部署后代码又有改动，会拒绝覆盖。回滚路径已静态检查，本轮没有对正在恢复工作的生产环境执行回滚演练。

后续在 72 小时、七天窗口比较人工登录流程次数、成功读取量、验证/限流次数和资源占用。当前只能确认工程改造与即时验收结果，不能声称登录寿命已显著延长。
