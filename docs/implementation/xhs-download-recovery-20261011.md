# 小红书下载受阻修复与运行验收（2026-10-11）

公开版本已匿名化本机入口和任务标识；原始验收记录保留在本地。
代码和运行保护已上线。按用户要求，466 个具备重试条件的任务已重新入队，检查点得到保留；恢复期间另有一条 CCR 响应截断任务进行了一次保留检查点的重试。电脑端已重新登录并验证原账号，两条小红书来源均完成下载、知识发布及真实统一检索验收，其余可重试任务已放行，原三个同步定时器已恢复。997 个缺少有效来源链接的任务仍受阻。

## 已确认原因

- 小红书笔记请求曾重定向到 `/404`，错误码 `300031`；有令牌的来源也出现登录跳转。
- 登录工具实际打开的页面显示“安全限制：IP 存在风险，请切换可靠网络环境后重试”，平台码 `300012`。因此不能把全部失败归因于缺少令牌，也不能认为重新生成二维码即可解决。
- `ProviderUnavailable` 未显式传入 `code` 时，流水线原来只保存异常类名，丢失了具体原因；默认不可重试导致大量任务进入 blocked。
- 八条历史 CCR 失败来自当时的模型路由不匹配。当前同一配置模型已有成功请求；没有为此修改模型或路由设置。

## 实现

- 只将格式合法的符号错误自动保留为错误码；普通异常正文不会进入错误码。识别登录跳转、笔记不可访问、平台验证限制，以及可重试的 HTTP 429/5xx、网络和浏览器超时。
- 新迁移 `0010_xhs_download_gate.sql` 为现有控制表增加独立的小红书认证暂停及冷却字段。首次认证失败停止领取需要访问小红书的下载任务；暂时故障最多三次尝试，间隔 5 秒、30 秒，累计三次失败后冷却 60 秒；成功下载清零临时失败计数。
- 来源暂停同时约束任务准入和下载领取，避免被暂停来源填满流水线入口。其他来源、已下载资产及下游阶段不受此来源暂停影响。登录暂停必须在真实认证和来源验证成功后显式解除。
- 桌面详情与网页控制台显示来源暂停原因；历史任务区分“需要有效来源链接”和“待来源验证”。日志只允许输出格式受限的数字平台码。
- `scripts/recover_xhs_downloads.py` 按同一笔记 ID，从任务、历史合并记录和知识来源元数据恢复完整链接或作者信息。不能按标题猜测来源。应用前写入 0600 私有前镜像；事务内仅更新仍然受阻且原 payload 未变化的目标，保留检查点和旧知识，不触发重排。
- `--probe-job` 最多检查两个指定任务，核对原账号绑定并解析来源；不会解除来源暂停、下载媒体或调用模型。
